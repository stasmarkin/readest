# readest-library

CLI всегда зови по абсолютному пути `~/.local/bin/readest` (в `PATH` демона его может не быть). Тексты команд — на английском, коды выхода: 0 — успех, 1 — ошибка операции, 2 — ошибка использования, 3 — нужен вход.

## Когда звать

- Вопросы о библиотеке: какие книги есть, что в группе, сколько прочитано.
- Заметки и выделения книги — пересказать, найти цитату, собрать конспект.
- Залить книгу — только по явной просьбе пользователя.
- Удалить или заменить конкретную книгу — только по прямой просьбе пользователя про эту книгу.

## Команды

```sh
~/.local/bin/readest whoami
~/.local/bin/readest books --json
~/.local/bin/readest books --search "лем"
~/.local/bin/readest notes "солярис"            # Markdown в stdout
~/.local/bin/readest notes 4a0cf9 --format json  # hash или префикс от 6 символов
~/.local/bin/readest upload ~/Downloads/book.epub --group "Фантастика/Лем" --dry-run
~/.local/bin/readest upload ~/Downloads/book.epub --group "Фантастика/Лем" --json
~/.local/bin/readest upload ~/Downloads/book-v2.epub --replace <hash> --json
~/.local/bin/readest delete <hash> --json
```

`<книга>` у `notes` — полный hash, префикс hash от 6 символов или часть названия. Несколько совпадений — ошибка со списком кандидатов: выбери по hash7 или уточни у пользователя.

`upload` не задаёт вопросов. С `--json` в stdout ровно один JSON-массив `{file, status, reason?, hash, title, group?, metaHash, uncertain?}`, диагностика — в stderr. `status`: `uploaded`, `reuploaded`, `revived`, `skipped` (`reason`: `already` — уже залита, `duplicate` — та же книга под другим hash), `replaced` (у `--replace`), `error`. `delete --json` — массив `{hash, status, reason?, uncertain?}`: `deleted`, `skipped` (`missing`), `error`. Повтор того же файла безопасен: залитая книга даст `skipped`, прерванная заливка продолжится. Сбой всего запуска — код 1 и `[]` в stdout; лок, перехваченный посреди запуска, — `error` с `uncertain` у текущего файла; код 3 с текстом `session changed to another account` — в профиле вошли под другим аккаунтом, запусти заново.

## Правила

- Код 3 (`login required`) — попроси пользователя войти самому: `! readest login --email <его email>`. Пароль у пользователя не спрашивай и в команды не подставляй.
- Заливай только по просьбе пользователя. Если группа неоднозначна (пользователь не назвал её точно, а похожих групп в `books` несколько) — сначала `--dry-run`, покажи решение и спроси.
- `skipped: duplicate` — книга уже есть под другим файлом; `--allow-duplicate` — только если пользователь прямо хочет копию.
- После `uploaded` книга не появилась на устройстве — проверь с пользователем, что в клиенте включён облачный синк Readest, и подожди или запусти синк в клиенте.
- `delete <hash>` и `upload <файл> --replace <hash>` — только когда пользователь прямо попросил удалить или заменить эту книгу: перед вызовом покажи по `books` название и hash7 и получи подтверждение. Массовые удаления и замены — не здесь, их делает синк клиппингов. `--replace` переносит группу и прогресс; позиция чтения не переносится, заметки после правки текста могут сместиться (скажи пользователю).
- `error` с `uncertain: true` — исход неизвестен: повтори ту же команду (замену — с `--resume`).
- Переименовывать и перекладывать книги, править прогресс и заметки CLI не умеет — не обходи это прямыми запросами к API.
- Заметки — в разговор. Файл — только по просьбе, в `~/Downloads` (`--out ~/Downloads/<название>.md`).
- `notes` упал с подсказкой про `git submodule update` — сообщи пользователю: в чекауте нет подмодуля `packages/foliate-js`.
