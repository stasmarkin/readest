# clippings-sync

Каждый час зеркалит папку Obsidian `06_Clippings` в группу `Clippings` selfhost-библиотеки Readest. Каждый `.md` становится EPUB со вшитыми картинками (pandoc). Новый файл заливается, изменённый заменяет свою книгу (группа, прогресс и заметки сохраняются), удалённый уходит из библиотеки. Направление одно: Obsidian → Readest. С сервером синк работает только через CLI `readest` (`selfhost/cli`).

## Установка

Нужны Node 24, `pandoc` (`brew install pandoc`, проверено на 3.14) и CLI `readest` в `PATH`. Без `pandoc` или `readest` синк выходит с кодом 2.

```sh
ln -sfn "<чекаут>/selfhost/clippings/clippings-sync.ts" ~/.local/bin/readest-clippings-sync
readest login --email me@example.com
readest-clippings-sync --dry-run      # план: что будет залито, заменено, удалено, что надо скачать
readest-clippings-sync                # первый прогон заливает все клиппинги
ln -sfn "<чекаут>/selfhost/clippings/clippings-sync.yaml" ~/Workspace/Projects/_system/dagu/dags/clippings-sync.yaml
```

DAG `clippings-sync.yaml` запускает `readest-clippings-sync --notify` в :20 каждого часа (dagu, один прогон за раз, пропущенные во сне часы не доигрываются).

## Запуск

```sh
readest-clippings-sync [--dry-run] [--allow-mass-delete] [--notify] [--vault DIR] [--state DIR]
```

- `--vault` — по умолчанию `/Users/stasmarkin/Workspace/Obsidian/06_Clippings`; хранилище только читается. Клиппинг — любой `.md` внутри, кроме скрытых файлов и каталогов (`.obsidian`, `.trash`). Файл нулевой длины пропускается как недописанный.
- `--state` — по умолчанию `~/.local/state/readest-clippings/`.
- `--dry-run` печатает план и незавершённые операции; ничего не пишет (state, кеш картинок, outbox), ничего не качает и не зовёт `upload`/`delete`. Картинка без кеша печатается как «требуется скачивание», отсрочка — как условная.
- `--allow-mass-delete` снимает защиты от массового удаления (см. ниже); им же подтверждается удаление последних клиппингов.
- `--notify` — при потере входа одно сообщение через `levi notify`; следующее — только после прогона, в котором вход снова работал.

Вывод: строка на действие (`uploaded|replaced|deleted|deferred|recovered|optout|error <файл> — <деталь>`) и итог `итог: +N ~M -K, отложено D, ошибок E` (восстановленные операции в счёт не входят).

Коды выхода:

- 0 — всё сделано (отложенные меньше суток и неудачная дособорка — норма); `уже идёт` — другой прогон держит лок;
- 1 — ошибка хотя бы одного файла, неизвестный исход операции (повторится в следующем прогоне), потерянный лок или первая заливка без части картинок после суток ожидания;
- 2 — аргументы, окружение, нечитаемый vault, state от другого vault или сервера, защитный стоп;
- 3 — нужен `readest login` или в профиле теперь другой пользователь.

## Как устроено

- `state.json` — реестр «файл → книга» (`files`), все когда-либо созданные синком hash (`history`), файлы с книгами, удалёнными вручную (`optOut`), отложенные файлы (`pending`) и журнал незавершённых операций (`ops`). State привязан к vault, серверу и пользователю: все вызовы `readest` идут с `--expect-user`.
- Каждая запись на сервер: EPUB в `outbox/` → операция в журнал → `readest` → реестр → удаление из outbox. Сбой на любом шаге доводит следующий прогон (`recovered`), книг без владельца и дублей не остаётся.
- Сборка детерминирована: одинаковые исходник и картинки дают одинаковые байты (`SOURCE_DATE_EPOCH` из `published`/`created`, кеш картинок). Хеш исходника вшит в OPF (`dc:relation`), так что любая правка меняет hash книги.
- Картинки кешируются в `images/`. Публичные качаются напрямую, `*.yandex-team.ru` — через залогиненный Chromium (`web`, сессия `clippings-sync`). 404/410, больше 25 MiB или не картинка — ссылка «[картинка]» навсегда; 401/403/429/5xx, таймаут, нет Chromium или входа — временно. Временная ошибка дольше 3 суток и 3 попыток считается постоянной.
- Новый или изменённый файл с временно недоступными картинками ждёт до 24 ч (`deferred`), потом заливается со ссылками вместо них. Такая книга раз в сутки дособирается, если появились её картинки.

## Защиты

- Пустой vault при непустом реестре — удаления не выполняются, код 2.
- Исчезло больше `max(10, 20 %)` файлов реестра за прогон — удаления не выполняются (остальное делается), код 2.
- В снимке библиотеки нет больше `max(10, 20 %)` книг реестра или нет ни одной — `optOut` не записывается (защита от пустого или неполного ответа сервера), код 2. Если ты правда удалил в Readest все книги клиппингов — подтверди тем же флагом.
- Ошибка чтения файла vault (кроме исчезновения) — код 2 без удалений. Битый симлинк `.md` или симлинк наружу vault не публикуется и не считается удалением.
- Все стопы снимает `--allow-mass-delete`. Операции из журнала довершаются и при стопе: их одобрил прошлый прогон.

## Книга, удалённая в Readest вручную

Синк её больше не трогает: файл уходит в `optOut`, правка, исчезновение и возврат файла книгу не вернут. Чтобы вернуть, переименуй файл в Obsidian — это новый клиппинг. Перенос книги в другую группу ничего не ломает: замена сохраняет группу старой строки.

## Начать с нуля

Удали группу `Clippings` в Readest (все её книги) и каталог state, затем запусти синк заново. Если state потерян, а книги остались, синк не узнает свои книги: живая книга с тем же hash даст `conflict`. Тогда тоже — удалить группу и state.

## Ограничения

- Переименование файла — это «удалён + новый»: другой `identifier`, а значит другой metaHash; заметки старой книги к новой не привяжутся. То же при смене `title` или `author` в frontmatter.
- Позиция чтения после замены не переносится (CFI старой версии указывал бы не туда); виден процент из прогресса. Заметки доезжают по metaHash, но после правки текста выше выделения подсветка может сместиться или пропасть.
- Новая версия pandoc может дать другие байты: затронет только пересобираемые файлы. Вернувшийся после удаления файл тогда даст `uploaded`, а не `revived`, заметки найдутся по metaHash.
- Ссылки на локальные картинки ищутся по тексту Markdown (`![](путь)`, `<img src>`, определения ссылок); картинки вне vault и симлинки наружу не читаются.
